# Wave 0, Ticket 0.1 — Inspect Repository

Wave: Repository Discovery and Technical Plan

Status: Complete

## Goal

Establish the current architecture and verification baseline before feature implementation.

## Findings

- Frontend: Next.js 15.1.2 App Router, React 19, strict TypeScript, Tailwind CSS, and reusable UI primitives under `components/ui`.
- Backend: Next.js route handlers under `app/api`; there is no separate backend service.
- Database: Supabase PostgreSQL accessed directly with `@supabase/supabase-js`; there is no ORM or checked-in migration directory.
- Authentication: Clerk. Protected route handlers call `auth()` and use the Clerk user ID.
- Existing course model: the `courses` table and `/api/courses` route represent the shared course catalog. Imported student courses must not overload this model.
- Existing API style: route handlers return `NextResponse.json`, authenticate locally where needed, and call `lib/supabase.ts`.
- Existing upload flow: none.
- Existing tests before this work: none.
- Existing calendar code: none.
- Existing environment: Clerk and Supabase variables are configured; no LLM provider variable is present.
- Working tree: pre-existing edits in planner, navigation, and package files must be preserved.

## Verification Baseline

- `npx tsc --noEmit`: passes.
- `npm run lint`: has pre-existing failures in `app/checkCourse/page.tsx` and `components/Nav.tsx`.
- `npm run build`: application compilation was initially blocked by unavailable Google Fonts network access.
